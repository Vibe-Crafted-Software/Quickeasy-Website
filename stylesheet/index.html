Style sheet

Every token and component in assets/css/main.css, rendered live. Flip the theme toggle in the header to check both palettes.

This page is deliberately unlisted — nothing links to it, it is noindex so it stays out of sitemap.xml, and it carries no data-pagefind-body, so site search will never return it.

01 — Colour

Tokens

Every colour comes from a token. Hardcode a literal and it will not theme. The dark palette redefines these same names under :root[data-theme="dark"].

Ink

--ink Headings, strongest text
--ink-2 Sub-headings, nav links
--body Body copy
--muted Meta, placeholders
--graphite Secondary grey

Surfaces & lines

--bg Page background
--surface Cards, inputs, menus
--paper Grey band tone
--line Borders
--line-2 Softer borders

Accent

--red Accent role — holds an ink tone in the monochrome system
--red-dk Accent, darkest
--red-wash Accent wash

The --red* names are historical. In the monochrome system they hold ink tones — red survives only on the QuickEasy logo image itself.

05 — Layout

Section bands

Bands alternate white / paper / white down every page. Two same-tone bands touching read as one oversized slab — the tests catch it.

.section — white band. The default.

.section .section--paper — grey band. Tone comes from --paper alone.

.section .section--paper .section--ink — grey band with rules top and bottom. --ink only adds the rules; it never sets the tone.

The hero's gradient ends on paper, so it counts as a grey band and the first section under it must be white. Fix collisions in the page markup, never with an adjacent-sibling override in main.css.

09 — Utilities

Utilities & conventions

  • .container — the max-width wrapper (--maxw) with the side gutter. Every band needs one.
  • .center — centres text, and centres a .lead inside it.
  • .sec-head — the eyebrow + heading + lead cluster at the top of a band.
  • .gs — grayscales an image. Site imagery is grayscale; the QuickEasy logo stays in colour.
  • .visually-hidden / .sr-only — hides a label visually while leaving it for screen readers.
  • .table-wrap — wraps a wide table so it scrolls horizontally instead of the page doing so.
  • --ctl-h — the height of the small header controls (search, theme toggle, language switch, menu button). They set height:var(--ctl-h) rather than sizing to their content, so a 20px glyph and 13px of text still line up. It steps down on narrow screens; change it there, not per control.
  • .hero-art — the landing-page hero illustrations. Inline SVG, not image files, so every fill is a token and the artwork themes with the page instead of turning into a grey slab in dark mode. Strictly greyscale, one per page, 640×420. Flip the theme toggle on this page to check.
  • .nav-toggle — the menu button, shown below 1040px. It carries a visible .nav-toggle__label caption alongside the glyph, which is hidden below 420px to save bar width — so the button keeps its own aria-label and the caption is aria-hidden, giving it one stable accessible name at every size.
  • .hero p + p — hero paragraphs have margin:0, so a .lead followed by a body paragraph needs this rule to sit apart. Single-paragraph heroes (blog posts) are untouched.

New components must use the tokens above — never hardcode a light colour, or it will not theme. The header and footer are duplicated into every page, so change them with a one-off Node sweep, not by hand.
